## 冲突处理

以下冲突文件已完成三方合并并暂存，处理原则为保留二开行为、吸收不冲突的上游修复：

1. `backend/internal/handler/endpoint.go`、`endpoint_test.go`
   - 保留 LinkCode 自定义端点归一化规则，合入上游端点协议兼容。
2. `backend/internal/handler/openai_gateway_count_tokens.go`
   - 保留本地输入 token 计数和错误处理，合入上游 Responses 输入 token 预检能力。
3. `backend/internal/handler/ops_error_logger.go`
   - 保留本地运维错误记录和提示审计字段，合入上游错误透传规则支持。
4. `backend/internal/server/routes/gateway.go`
   - 保留本地网关路由、免费分组、对话站限制和模型路由入口，合入上游新增协议路由。
5. `backend/internal/service/openai_gateway_count_tokens.go`
   - 保留 OAuth/二开上游可能不支持 `/input_tokens` 时的本地 token 估算回退，避免可选端点 404 影响健康度。
6. `backend/internal/service/openai_gateway_forward.go`
   - 保留本地模型路由、故障转移、提示审计、免费分组和图片对象存储逻辑，合入 DeepSeek 原生 Responses 及 CN Provider 协议选择。
7. `backend/internal/service/openai_gateway_response_handling.go`
   - 保留 LinkCode 首字统计契约；OpenAI Responses 仍使用尝试级首输出暂存，避免故障转移时把前一账号的前导事件泄露给客户端。
8. `backend/internal/service/openai_visible_ttft_test.go`
   - 保留结构性首字统计测试，并与上游新增的可见输出相关行为共同保留。
9. `backend/internal/service/upstream_path_guard_test.go`
   - 保留本地上游路径防护测试，合入上游新增路径协议覆盖。

另外，`IsOpenAIResponsesInputTokensRequestPath(path string)` 与 Gin Context 版本分别保留，避免上游合并时同名 API 冲突；相关测试已重命名为路径版和上下文版。
