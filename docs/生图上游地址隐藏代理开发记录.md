# 生图上游地址隐藏代理开发记录

## 背景

部分 OpenAI 兼容生图上游会在响应中直接返回供应商图片地址，例如
`https://usawest.up.railway.app/v1/images/proxy?...`。该地址会暴露上游来源，且中国大陆用户可能无法直接访问。

## 实现方案

- 中转站收到生图 JSON 或 SSE 响应后，递归识别 `url`、`image_url` 字段中的远程 HTTP(S) 图片地址。
- 为每个上游地址生成 24 小时有效的 192 位随机令牌。
- Redis 仅保存 `image_proxy_url:{token} -> 上游 URL`，不保存图片内容。
- 返回客户端的地址改为 `https://api.linkcode.site/v1/images/proxy/{token}`。
- 用户访问代理地址时，中转站实时拉取上游图片并直接流式返回，不落盘、不上传对象存储、不使用 302 跳转。
- `b64_json`、`data:image/...` 等内嵌图片保持原样。
- 代理地址沿用用户实际访问的本站域名；通过 `api.linkcode.site` 请求时返回该域名，通过 `api-fast.linkcode.site` 请求时沿用快速线路域名。
- 异步生图仍沿用项目原有的对象存储转存机制；本次无落盘代理主要处理同步生图 JSON 和 SSE 返回。

## 安全限制

- 只允许 HTTP/HTTPS 上游地址，禁止 URL 用户信息。
- 在拨号层阻止 loopback、内网、链路本地、CGNAT 和云元数据地址，防止 SSRF 与 DNS rebinding。
- 最多跟随 3 次重定向，每次重定向重新执行地址校验。
- 只返回 PNG、JPEG、WebP、GIF、AVIF、BMP，拒绝 HTML、JSON、SVG 等内容。
- 单张图片最大 50MB，请求总超时 2 分钟。
- 不向上游转发用户 Cookie、Authorization 等请求头。
- Redis 写入或代理能力异常时，响应改写为本站不可用地址，避免退回并泄露真实上游 URL。

## 缓存与流量

- 图片内容不在中转站持久化。
- 代理响应设置 `Cache-Control: public, max-age=3600`，允许浏览器和 Cloudflare 短期缓存。
- 未命中缓存时，图片流量会经过上游、中转站和线路机。
- Redis 令牌 24 小时后自动删除；上游图片提前失效时，代理地址也会失效。

## 发布说明

- 不新增数据库表，不需要执行 SQL。
- 使用现有 Redis 和 `api.linkcode.site`，不需要新增域名。
- Nginx 需继续保留 `Host` 与 `X-Forwarded-Proto` 请求头；仓库现有部署说明已包含对应配置。
- 服务器拉取代码并重新构建应用后生效。

## 同步生图统一对象存储（2026-08-13）

在原有 URL 隐藏代理基础上，继续复用后台“生图对象存储”配置，将同步生图结果统一转存：

- 上游返回 `b64_json`：内存解码后上传 S3，删除 `b64_json`，返回 `data[].url`。
- 上游返回 `data:image/...;base64,...`：内存解码后上传 S3。
- 上游返回远程 `url` 或 `image_url`：通过带 SSRF、DNS rebinding 防护的下载客户端读取，再上传 S3。
- 非流式响应和流式最终完成事件均支持转存；流式局部预览帧保持原协议，避免破坏渐进预览。
- 上传设置未启用时保持原行为；上传失败或超时时按原 Base64/URL 代理逻辑降级，不让对象存储故障导致生图请求失败。
- 同步转存超时为 30 秒，不落本地磁盘。
- 对象 Key 使用随机令牌，避免请求之间重名。

后台原“异步生图对象存储”改名为“生图对象存储”，同一套配置同时用于同步与异步生图。配置“公开访问域名”后，Base64 和第三方 URL 最终都会返回统一域名；未配置时返回 S3 预签名链接。
