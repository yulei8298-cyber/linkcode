## 4. 与二开的兼容修复

### 4.1 余额在途预留 × 每日免费分组（重要）

- 官方新增"余额模式在途预留"（`billing.inflight_reservation.enabled` 默认 `true`）：请求准入时按估算费用在 Redis 预占余额，`缓存余额 - 在途合计 < 估算` 且已有在途请求时返回余额不足。
- 冲突：LinkCode 每日免费分组只记免费账本、不扣余额，用户余额通常为 0；同一用户的第二个并发请求会被误判"余额不足"。
- 处理：与订阅模式一样豁免免费分组：
  - `internal/handler/gateway_inflight_reservation.go`：`apiKey.Group.IsFree` 时直接放行，且早于 `fail_closed_on_unpriced` 判断；
  - `internal/service/billing_inflight_reservation.go`：`reserveInflight` 对 `group.IsFree` 不登记预留（纵深防御，覆盖 WebSocket 等直接调用 service 的路径）。
- 官方同时在余额扣费后同步扣减余额缓存（`syncBalanceCacheAfterDeduction`），本地对免费分组本就不走该函数，无需调整。
- 新增测试：`internal/handler/gateway_inflight_reservation_free_group_test.go`、`internal/service/billing_inflight_reservation_free_group_test.go`（免费分组余额为 0 时并发不被拒绝、不估算不登记；普通余额分组仍按余额拦截）。

### 4.2 Codex 远程模型目录

官方 UseKeyModal 新增 `model_catalog_url` 远程目录。本地保留 Codex `base_url` 为网关根地址；远程目录 URL 由官方 `buildCodexModelCatalogUrl` 生成为 `/v1/models`（根路径与 `/v1` 下挂载同一 models handler，均可用）。官方新用例中 `base_url` 期望调整为根地址。

### 4.3 API Key 创建限制

官方新增 `api_key_create.max_active_per_user`（默认 200）与 `max_per_user_per_hour`（默认 60）。已确认本地 LobeHub SSO、对话站等二开流程不会自动批量创建 Key（只有用户在 Key 管理页主动创建会走 `APIKeyService.Create`），默认值对现有业务无影响；如有运营批量建 Key 需求，可在配置中调整或设为 0 关闭。

## 7. 需要关注的默认行为变化

1. 余额模式请求默认启用在途预留：同一用户余额不足以覆盖多个并发请求的估算费用时，后续并发请求会返回余额不足（免费分组、订阅分组、简单模式不受影响）。Redis 异常时放行。
2. API Key 创建默认限制为每用户 200 个未删除 Key、每小时 60 次，删除不返还次数。
